# Nuno Crato — personal website (nunocrato.org)

Static site, no build step. Everything published lives in `docs/`; GitHub Pages serves that folder as-is
(Settings → Pages → branch `main`, folder `/docs`). Pushing to `main` redeploys automatically. Netlify is no longer used.

## Layout

- `docs/*.html` — seven pages: `index`, `research`, `publications`, `education`, `presentations`, `media`, `about`.
  Served at clean URLs (`/research`, `/media`, ...). Styles are in `docs/style.css` (the home page also has an inline `<style>`).
- `docs/presentations/YYYY-MM-DD-short-slug.pdf` — slide decks. Name new ones the same way.
- `docs/wp-content/uploads/...` — files migrated from the old WordPress site. **Never rename or move these:**
  old links from other websites, Google and QR codes in slides depend on the exact paths.
- `docs/images/` — images used by pages (home-page thumbnails are 84px squares, cropped to cover).
- `docs/documents/biographies/` — biography PDFs (EN, PT, ES).
- `docs/old-links.js` — loaded by `index.html`; sends old WordPress addresses (`/?p=…`, `/?page_id=…`, `/?cat=…`) to the
  right section (GitHub Pages has no server redirects). Generated: `python3 tools/make_old_links.py tools/old-wp-inventory.json docs/old-links.js`.
  `tools/old-wordpress-redirects.txt` is the old Netlify rule list, kept for reference only.
- `docs/pt/*.html` — Portuguese version, **generated** from the English pages: `python3 tools/make_pt.py` (also rewrites the EN/PT
  switch and hreflang tags in the English pages). Never edit `docs/pt/` by hand. New English text (descriptions, labels) goes into
  `tools/pt_strings.py` first; titles of works stay in their original language. Workflow for any change: edit the English page,
  add translations to `pt_strings.py`, run `make_pt.py`, then the checker.
- `docs/events.html`, `docs/pt/events.html`, `docs/events.ics` — **generated** from `tools/events.json` (upcoming and past events,
  "add to calendar" links, calendar file). To add an event: edit `tools/events.json`, then run the build chain below. The page also sorts
  itself into upcoming/past in the visitor's browser, so nothing goes stale between rebuilds. Move finished events' details into the
  Presentations/Media pages as usual.
- `docs/sitemap.xml`, `docs/robots.txt` — generated by `tools/make_sitemap.py`.
- `docs/404.html` — not-found page. `docs/.nojekyll` must stay. `docs/CNAME` holds the custom domain once DNS is switched.
- `tools/check_site.py` — link checker (see below).

## Conventions

- Newest first, inside year sections (`<h2 class="sec">2026</h2>`). English descriptions, original-language titles.
- Links to own files are relative, no leading slash (`presentations/...pdf`, `research`, brand link `./`), never
  `https://www.nunocrato.org/...`. (`404.html` is the exception: it uses absolute paths.)
  The only absolute own-domain URLs are the canonical/`og:`/`twitter:` meta tags (social cards need absolute URLs).
- The EN/PT switch is generated by `make_pt.py`; see the `docs/pt/` rule above.
- No trackers, no build tooling, no frameworks. Keep pages plain HTML.

## Features added October 2026

- **CV**: `tools/make_cv.py` builds `docs/documents/cv/nuno-crato-cv-2026.pdf` (edit the data in that script; `build.sh` runs it). It is linked on About.
- **Contact section** on About (`#contact`): the email is assembled by JS from `data-u`/`data-d` (spam protection). Only the ISEG address is used;
  a nunocrato.org mailbox would need the Bluehost email hosting kept.
- **Media page**: client-side search + year filter (script at the bottom of `media.html`, builds its own UI, works in EN/PT) and an "Archive" link
  (Wayback `/web/2/<url>`) next to every external press link.
- **Event and book pages**: `tools/make_items.py` writes `docs/events/<date>-<slug>.html` and `docs/books/<slug>.html` (+ `docs/pt/...`) with JSON-LD
  (Event / Book). Events come from `events.json`; books come from the `.bookcard` blocks in `publications.html` (it adds the "Details" link itself).
  New book = add a card to `publications.html` (title, `.bm` "Publisher · year", description div) and run `tools/build.sh`.
- **Structured data**: Person JSON-LD in `index.html` and `about.html`.
- **Weekly checks**: `.github/workflows/weekly-checks.yml` (Mondays) runs `check_site.py`, `check_external.py` (opens a GitHub issue if links are dead) and
  `archive_links.py` (asks the Internet Archive to save press links that have no copy). Can also be run by hand from the Actions tab.
- Search Console: add the property `https://www.nunocrato.org/`, submit `https://www.nunocrato.org/sitemap.xml`.

## Markup to copy

Presentations page (`presentations.html`) and Media page (`media.html`) use the same entry block:

```html
<div class="entry"><div class="when">2026 · Sep</div><div><div class="et">Title</div><div class="ed">One-line description, place, date.</div><a class="dl" href="presentations/2026-09-17-slug.pdf">PDF</a></div></div>
```

External links add `target="_blank" rel="noopener"`. Entries without a file simply omit the `<a class="dl">`.

Home page "Recent activity" (`index.html`) shows the 5 most recent items; add new ones on top and drop the oldest
(make sure the dropped item still exists on the Media page):

```html
    <a class='feed-item' href='media'>
      <img class="feed-thumb" src="images/some-thumb.jpg" alt="">
      <div>
        <div class="feed-when">October 2026 · Book presentation</div>
        <div class="feed-title">Title · place</div>
      </div>
    </a>
```

## Build chain (run from the repo root after any content change)

```
tools/build.sh
```

(`build.sh` runs, in order: `make_cv.py`, `make_docs.py rewrite`, `make_items.py links`, `make_pt.py`, `make_docs.py build`, `make_events.py`, `make_items.py build`, `make_sitemap.py`, `check_site.py docs`.)

**PDF links open a preview page, not a download.** Link a new PDF in an English page the normal way (`<a class="dl" href="presentations/x.pdf">PDF</a>`);
`build.sh` registers it in `tools/documents.json`, rewrites the link to `view/<slug>`, and generates `docs/view/<slug>.html`,
`docs/pt/view/<slug>.html` and a first-page thumbnail (`docs/view/thumbs/`). Those generated files are not edited by hand.
Viewer pages use absolute paths (`/style.css`) like `404.html`. Entries in `events.json` that link to a PDF are routed through the viewer too.

Images: shrink before adding (photos ≤ ~1400 px wide, JPEG quality ~82). Every `<img>` needs `width`/`height`, `loading="lazy"`
(except the first image on the home and About pages). Do not rename files under `docs/wp-content/` (shrinking them in place is fine).

## Checking a change

1. Serve the folder: `python3 -m http.server 8000 --directory docs` and open the changed pages.
2. Run `python3 tools/check_site.py docs` — it must report `problems: 0`.
3. Commit and push to `main`.
